# Изменения интерфейса — 5.00.03

Версия исходников **5.00.03**, versionCode **211**. Реализованы выбранные пункты 2–4 анализа и следующий этап (пункты 5–8). Пункт 1 о переработке очистки хранилища не включён: существующие подтверждения и состав общей очистки не изменялись.

## Сообщения и голосовые

- Для обычного неподтверждённого сообщения показано «Ждём подтверждения», для неоднозначной записи с `confirmationBlocked` — «Проверьте вручную». Информация передаётся из Outbox в модель строки. Различаются и значки обычного ожидания/ошибки.
- В меню неподтверждённой записи основное действие — «Проверить переписку». Повтор требует явного подтверждения предупреждения о возможном дубле. «Убрать из очереди» обозначает удаление локальной записи, а не сообщения у собеседника. Удаление по-прежнему можно отменить.
- Голосовое получает локальную карточку с длительностью: загрузка → ожидание сервера → принято / не подтверждено / не отправлено. Результат больше не зависит только от исчезающего Snackbar.
- Метаданные карточек хранятся в приватных SharedPreferences (до 100 последних записей). После повторного открытия/перезапуска незавершённые операции становятся требующими проверки, а не заведомо неотправленными. Сохраняются операция, переписка, длительность, время, состояние и идентификатор документа; аудиофайл, токены и ключи доступа в этом хранилище отсутствуют.
- Страница сообщает идентификатор документа после `docs.save`, а также в результате отправки. Карточка заменяется серверным голосовым только при совпадении документа в той же переписке. По времени, похожему тексту или длительности совпадение не угадывается. Если идентификатора недостаточно, пользователь может обновить переписку и затем скрыть карточку вручную.
- Нет автоматического повтора голосового и кнопки, обещающей повторно отправить уже удалённый локальный аудиофайл. Это карточка результата, а не новый аудиокэш. Предпрослушивание и повторное использование записанного файла в этот объём не входят.
- Карточки очищаются вместе с сохранёнными сообщениями и при выходе из аккаунта. Это подключение нового вида локальных данных к существующей очистке; интерфейс очистки из пункта 1 не перерабатывался.

## Вложения и удобство нажатия

- Над вводом есть постоянная строка: подготовка файла N из M, передача файла N из M, загрузка страницей VK и проверка отправки. Проценты неизвестной приложению загрузки VK не выдумываются.
- До финальной стадии доступна отмена. Она прекращает подготовку/передачу и вызывает существующий безопасный сброс композера, если файлы уже были приняты страницей. Текст и выбранный набор сохраняются; после ошибки текст не теряется из черновика из-за прежнего `sentDraft`.
- Поскольку событие страницы и нажатие отмены могут прийти почти одновременно, интерфейс не обещает отозвать сообщение, уже переданное серверу: после запроса отмены предлагается проверить переписку перед повтором. На стадии проверки отправки кнопки отмены нет.
- Перед открытием выбора файлов объясняются ограничения: 10 файлов, 12 МБ каждый, 24 МБ всего. Эти ограничения также видны в строке выбранного набора. Уже идущая загрузка не принимает запоздалые результаты выбора файлов; результаты старой переписки отбрасываются по поколению выбора.
- После нажатия отправки строка сохраняет состояние проверки. Если сообщение не появилось в истории вовремя, остаётся пояснение о необходимости проверить переписку; его можно закрыть.
- Области нажатия реакций и чипов файлов имеют минимум 48dp по обеим осям. Основные кнопки и доступные текстовые подписи сохранены.

## Веб-режим и навигация

- В сообщениях постоянно видна полоса «Открыта страница VK». Для ошибки чтения есть «Лёгкий экран», для входа — «Войти». Возврат к лёгкому экрану выполняется через пересоздание с сохранением ранее открытой нативной переписки; начатая перед fallback передача отменяется существующими правилами.
- В навигации используются короткие подписи «Чаты», «Группы» и обычные короткие названия остальных разделов. Заголовки страниц и полное боковое меню не переименованы.
- Для новых настроек подписи включены по умолчанию. Сохранённое значение `nav_labels=false` сохраняет компактный режим. Настройка действует и на нижнюю панель, и на боковую полосу; адаптация навигации по ширине/жестам Android остаётся прежней.

## Сохранение музыки

- В разделе музыки видны реальные счётчики общего источника progress: сохранено и осталось в очереди, включая поиск потоков отдельной страницей. Индикатор не заменяет системное уведомление — оба используют существующую очередь.
- «Остановить очередь» снимает неначатые задачи без дополнительного диалога. Если текущий трек ещё обрабатывается, прямо объясняется, что он завершит сохранение. Повторное нажатие во время остановки отключено.
- После ручной операции сохраняется результат существующего CacheBatch. Есть список ещё не сохранённых треков исходного набора; перед показом он повторно сверяется с кэшем, поэтому уже сохранённые другой задачей треки не называются неудачными. Автоматическое сохранение также передаёт итог в панель, сохраняя тихий режим без дополнительного Snackbar.
- Завершённый результат можно закрыть. Слушатель прогресса снимается при отсоединении панели от окна. После перезапуска процесса результат прошлой музыкальной операции не восстанавливается; метки реально сохранённых треков по-прежнему берутся из файлового кэша.
- Действия трека и списка называются «Сохранить без сети» и «Удалить с устройства». Последнее удаляет локальный файл, а не трек из музыки VK.

## Проверки и ограничения

- **109 изолированных JVM-тестов, 0 ошибок**, включая 8 новых проверок голосовых карточек (восстановление, поздний ответ, таймаут, точное сопоставление и исключение входящих/неподтверждённых сообщений) и проверку передачи признака ручного решения в UI-модель. В числе тестов — 5 локальных проверок настоящего Outbox с моделью границы сохранения.
- **22 JS-регрессии, 0 ошибок.** Дополнительно усилены проверки порядка стадий файлов и передачи идентификатора документа/операции в событиях голосового. Исполняются настоящие функции страницы с управляемой границей DOM/API/таймеров.
- **449 Kotlin-файлов без синтаксических ошибок** по PSI. Это не проверка Android-типов, зависимостей и сборки APK.
- Проверены XML, отсутствие дубликатов строк и разрешение Kotlin-ссылок на строковые ресурсы. Отдельно сравнены с 5.00.02 строки подтверждения очистки: они не изменены.
- В JVM-прогоне используются заглушки Android/JSON; **3 теста сериализации явно исключены**. Реальные SharedPreferences и разбор новых payload-полей в штатном Android/JVM-наборе в этом окружении не подтверждены.

Полная Android-сборка/APK/lint, настоящий VK, размеры и переносы на устройстве, клавиатура, поворот экрана и TalkBack здесь не проверялись. Ранее штатный Gradle останавливался из-за Java 11 JRE и отсутствующего модуля `jdk.unsupported.desktop`; нужна полноценная среда JDK 17 + Android SDK. Полный jsdom-набор также недоступен из-за отсутствующего модуля jsdom. Изолированные проверки не выдаются за успешную Android-сборку.

Перед выпуском проверить 320/360dp и планшет, шрифт 150/200%, светлую/тёмную/чёрную темы; отмену файлов в конце загрузки, уход в другой чат, перезапуск с активной карточкой голосового, поздний успех после таймаута, выход из аккаунта, возврат из веб-режима и остановку музыкальной очереди при активном треке. При больших шрифтах особенно проверить подписи навигации и сочетание текстовых кнопок в новых строках.

Штатные команды:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug assembleRelease --no-daemon
cd tests/js
npm ci
npm test
```

Без npm-зависимостей из корня проекта: `node review-checks.cjs`. Локальный результат — `CHECK_RESULTS.txt`. Распространяемый ZIP содержит исходники, без локальных компиляторов, зависимостей и бинарных результатов. **APK не собран и не подписан.**
