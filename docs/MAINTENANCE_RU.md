## Запуск
Android Studio → File → Open → корень репозитория → Sync → Run. Регистрация в VK не нужна.

Для Gradle выберите JDK 17: Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK.
Минимальная версия Android задана в `app/build.gradle.kts`: `minSdk = 26` (Android 8.0), `compileSdk = 35`.
Если редактор показывает `current min is 1`, откройте весь Gradle-проект (где лежит `settings.gradle.kts`)
и выполните Sync Project with Gradle Files. Проверьте, что синхронизация завершилась успешно; открытие отдельного
Kotlin-файла или неудачная синхронизация не подтверждают настройки Android-модуля. Не отключайте проверку NewApi:
API 29 в кэше музыки доступны только в ветках Android 10+ и обозначены `@RequiresApi` на вспомогательных методах.
Сборку из командной строки и запуск проверок см. в [README](../README.md).

### Обычный (release) APK в Android Studio
1. Откройте корень репозитория и дождитесь Gradle Sync.
2. Создайте ключ подписи: **Build → Generate Signed Bundle / APK… → APK → Create new…**. Сохраните `.jks` в надёжное место и запомните пароли: для всех следующих обновлений этого приложения нужен тот же ключ.
3. Скопируйте `keystore.properties.example` в `keystore.properties` рядом с `build.gradle.kts`, укажите путь к `.jks`, пароль хранилища, alias и пароль ключа.
4. В окне **Build → Select Build Variant…** выберите `release`. Выполните **Build → Build Bundle(s) / APK(s) → Build APK(s)**.

Готовые подписанные APK будут в `app/build/outputs/apk/release/`: для обычного телефона с ARM64 выбирайте `app-arm64-v8a-release.apk`; `app-universal-release.apk` подходит для разных архитектур, `app-x86_64-release.apk` — для эмулятора. Без настроенного ключа Gradle создаст неподписанные release APK, которые Android не установит. Не теряйте ключ: APK, подписанный другим ключом, нельзя установить поверх предыдущей версии.

## Интерфейс
- Меню разделов (4.50) зависит от навигации Android. Жесты (свайп от края — «Назад») — нижняя панель: Сообщения, Друзья,
  Сообщества, Музыка и «Ещё» (боковое меню целиком). Три кнопки или жест от края выключен — боковое меню свайпом от
  левого края и кнопкой ☰. Средняя ширина (от 600dp: планшет, складной, телефон боком) — полоса значков слева с теми же
  пунктами (4.58). На планшетах меню можно закрепить слева (Настройки → Навигация).
- Подписи под значками нижней панели и полосы слева (4.80) — Настройки → Навигация → «Подписи в нижнем меню»,
  по умолчанию выключены: только значки, панель ниже (56 dp вместо 80), название — при долгом нажатии.
- Вид меню можно выбрать сам (4.64): Настройки → Навигация → «Вид меню» — «Автоматически» (как выше), «Нижняя
  панель» или «Боковое меню» (всегда, при любой навигации Android и ширине экрана). Закрепление на планшете главнее.
- Сверху — название раздела или открытой страницы, «Обновить», «Открыть в браузере».
- Настройки — последний пункт меню. Первый экран — список разделов, каждый открывается своим экраном:
  Оформление · Навигация · Экраны приложения · Сообщения · Реклама и трекеры · Воспроизведение · Данные и вход · О приложении.
  «Для разработки» скрыт: открывается семью нажатиями на «Версию» (или виден, пока включён сбор данных страниц).
- Реклама и трекеры заблокированы по умолчанию; списки доменов — `AD_DOMAINS` и `TRACKER_DOMAINS` в `config/AppConfig.kt`.
- Тема по умолчанию тёмная; можно выбрать светлую или «как в системе» (переключается сама).

### Как устроен свой экран
1. Страница VK получает данные сама; `ResponseTap` (`assets/vk_lite/40_screens.js`) читает её ответы (один перехват fetch/XHR
   на все экраны), модуль экрана собирает из них сообщение и шлёт его через `createChannel` (не чаще раза в 200 мс,
   без повторов).
2. `PageBridge` разбирает сообщение по полю `type` и отдаёт тому экрану, который зарегистрировал этот тип
   (`bridge.on(TYPE, Payload::fromJson, ::onPayload)` в `init` своего `PageOverlay`).
3. `PageOverlay` решает, показывать ли свою панель, и ведёт общее поведение (запасной показ страницы, «Назад»,
   плашки «нет сети» / «обновить не удалось», очистка сохранённого). Панель (`MusicPanel`, `PeoplePanel`,
   `OwnerPanel`) реализует `ui/OverlayPanel.kt` и только показывает данные; индикатор, строка состояния и плашка —
   общие (`ui/PanelFrame.kt` + `layout/panel_chrome.xml`). Догрузка при прокрутке — `ui/LoadMoreTrigger.kt`.

Новый экран: файл-модуль в `assets/vk_lite/` (`ResponseTap.listenApi` + `createChannel`), модель с `TYPE` и `fromJson`,
панель (`OverlayPanel` + `<include layout="@layout/panel_chrome" />`) и наследник `PageOverlay`, который в `init`
регистрирует свой тип; в `MainActivity` — одна строка в списке `overlays`. Если экран сохраняет данные без сети —
категория в `offline/StorageCategory.kt` (тогда её можно удалить из настроек).

### Сохранённое → свежее без дёрганий
Правила одни для всех своих экранов (и для экрана сообщений):
- сохранённое показывается сразу; индикатор загрузки появляется с задержкой 300 мс — если сохранённое прочиталось
  быстрее, он не мелькает;
- свежее встаёт поверх (`ListMerge.refresh`): настоящий порядок сверху, ещё не догруженное из сохранённого ниже —
  список не сжимается до первой свежей порции; когда страница прислала весь список, удалённое уходит;
- строка, на которую смотрят, остаётся на том же месте экрана (`ui/ListUpdates.submitAnchored`); кто в самом начале
  списка — остаётся в начале и видит новое;
- изменённая строка перерисовывается без анимации, а уже показанная картинка не сбрасывается на заглушку
  (`ImageCache.load` с заглушкой-лямбдой);
- свежее не пришло за 12 секунд: показано сохранённое — плашка «Показано сохранённое: обновить не удалось»;
  показать нечего — страница VK;
- сеть вернулась: страница перезагружается, только если на экране сохранённое (свежее не трогается);
- сохраняется то, что на экране после слияния, и только если оно изменилось.

## Свой интерфейс сообщений
Настройки → Свои экраны → «Свой интерфейс сообщений» (включено). Когда включено, раздел «Сообщения»
показывается своими экранами: страница m.vk.com грузится в невидимом WebView, скрипт `assets/vk_reader.js`
читает из неё диалоги и переписку, приложение рисует их сам. Отправка — через тот же скрипт.
Если данные прочитать не удалось (иная вёрстка, нет входа), приложение показывает страницу сайта — но только
когда показать нечего. Если на экране сохранённые диалоги или переписка, они остаются с плашкой «Показано
сохранённое: обновить не удалось» (кнопка «Обновить» — повторить), как и на остальных своих экранах.
Селекторы страниц — `config/ReaderConfig.kt`; при смене вёрстки VK правьте их через chrome://inspect.

### Реальная вёрстка мессенджера VK (reforged)
Селекторы в `config/ReaderConfig.kt` подогнаны под новый React-мессенджер m.vk.ru:
- диалоги: приложение сначала читает список из данных, которые VK кладёт в страницу
  (`window.cur.apiPrefetchCache`, ответ `messages.getItems`), и только если их нет — скребёт DOM;
- переписка: `.ConvoHistory__messageBlock` / `.MessageText`, адрес чата `/mail/convo/{peer}`;
- ввод — contenteditable `[data-testid="vkme_composer_input"]`, отправка через `execCommand('insertText')`
  и кнопку `[data-testid="vkme_composer_send"]`.
Список сообщений в чате виртуализирован: в DOM только видимые сообщения, поэтому читается лишь
их часть. Это ограничение подхода со чтением страницы.

### Навязчивые окна VK
Окно «В приложении — ещё лучше», подсказки-онбординг и баннеры ищутся **по тексту**, а не по классам
(классы VK меняются при каждой сборке) и скрываются в момент вставки в страницу, до первой отрисовки.
Кнопка «Остаться в браузере» нажимается автоматически, чтобы VK запомнил отказ. Тексты чатов, постов
и комментариев не затрагиваются. Списки — `PROMO_CLICK_TEXTS` и `PROMO_HIDE_TEXTS` в `config/AppConfig.kt`.
Появилось новое окно — добавьте его заголовок в `PROMO_HIDE_TEXTS`.

### Реклама в ленте и группах
Работает в три слоя (включается настройкой «Скрывать рекламу»):
1. **Данные.** Из ответов API VK (`/method/...`, через `fetch` и `XMLHttpRequest`) и из данных, вшитых в страницу
   (`window.cur.apiPrefetchCache`), вырезаются элементы с `marked_as_ads` и типом `ads`. Реклама не попадает на экран.
2. **Вёрстка.** Запасной путь: блок с пометкой «Реклама» или `erid` скрывается целиком как элемент списка.
3. **Сеть.** Рекламные домены блокируются (`AD_DOMAINS` в `config/AppConfig.kt`).
Если реклама осталась, откройте страницу через chrome://inspect и найдите в Network ответ `/method/...` с ней:
поле, по которому её можно отличить, добавляется в `AD_KEYS` / `AD_TYPES` в `assets/vk_lite/20_ads.js`.

### Конец воспроизведения
Когда трек или видео доиграли до конца и следом ничего не началось, плеер в шторке закрывается сам
(через 3 секунды, чтобы не мигать между треками плейлиста: `ENDED_GRACE_MS` в `media/MusicService.kt`).
Обычная пауза плеер не закрывает: он остаётся на «паузе» и убирается по таймауту из настроек.

### Свой интерфейс сообщений: откуда данные
Страница m.vk.ru/mail грузится в невидимом WebView, а `assets/vk_reader.js` забирает данные, которые
мессенджер VK сам получает (ничего сверх этого не запрашивается):
1. ответы API `/method/...` (fetch и XHR, включая пакетные вызовы), данные в `window.cur.apiPrefetchCache`
   и JSON из WebSocket. Структура распознаётся по форме объектов, а не по именам методов;
2. вёрстка — если данных API нет, и для новых сообщений, пришедших без запроса (они показываются
   как черновые и заменяются настоящими, когда те появляются в данных).
Прокрутка вверх в приложении прокручивает список на странице — мессенджер догружает старые сообщения,
и они попадают в приложение. В беседах у входящих сообщений показывается имя автора.

`/clips…` и `/clip…` ведут на стартовый раздел, из данных API вырезаются блоки клипов и вложения-клипы,

### Скрытые разделы
Разделы с адресом (Лента, Рекомендации, Закладки, Маркет, Мини-приложения, Игры, Меню VK) — пункты в

### Свой список музыки
Настройки → Свои экраны → «Свой список музыки» (включено). В разделе «Музыка» поверх страницы
показывается простой список «Моих треков»: название, исполнитель, длительность, играющий трек выделен.
Нажатие на трек нажимает тот же трек на странице — звук играет плеер VK (ссылки на аудио у VK закрыты
и зашифрованы, обходить это приложение не пытается), поэтому уведомление и фон работают как раньше.
Данные: ответы `/audio?act=…` и атрибуты `data-audio` (`assets/vk_lite/50_music.js`), трек —
массив `[id, владелец, ссылка, название, исполнитель, длительность, …, [11] контекст, …, [14] обложка]`.
Кнопка «Страница VK» на панели переключает на обычную страницу; если список не пришёл за 12 секунд,
страница открывается сама.

Поиск (4.79): строка поиска над переключателем «Музыка / Плейлисты». Ищет сама страница музыки VK
(`/audio?section=general&q=…`), результаты — своим списком вместо «Моих треков»; стрелка «назад» в строке (или
«Назад») закрывает поиск. Треки исполнителя — долгое нажатие на трек в любом списке, нажатие на исполнителя в плеере,
долгое нажатие на трек в переписке: тот же поиск по имени, но в списке только треки этого исполнителя (переключатель
«Только …» показывает всё, что нашёл VK). У трека с несколькими исполнителями («A feat. B») — выбор, чьи треки.
Результаты поиска без сети не сохраняются; в журнал пишется только длина запроса, не он сам.

### Свой интерфейс по умолчанию и работа без сети
Сообщения и «Мои треки» по умолчанию открываются своими экранами (Настройки → Свои экраны). Если данные
не пришли при рабочей сети, экран сам переключается на страницу VK; вернуться можно кнопкой или в настройках.

Без сети (`offline/`):
- `OfflineStore` — последние полученные диалоги, переписки (200 собеседников, по 1000 сообщений) и «Мои треки»
  во внутренней памяти приложения. Показываются сразу при открытии, без сети — вместо страницы.
- `NetworkMonitor` — когда сеть появляется, экран сам перезагружает данные.
- `ImageCache` — аватары, обложки и фото из сообщений сохраняются в исходном разрешении (фото — `orig_photo`
  или самый большой размер), на экране показываются уменьшенными. Просмотр на весь экран — `PhotoViewerActivity`
  (щипок, двойное касание). Размер кэша — Настройки → Данные и вход → «Место под сохранённые фото» (по умолчанию 1 ГБ), старые файлы удаляются первыми.
- Удаление — Настройки → Данные и вход → «Хранилище»: по категориям (`offline/StorageCategory.kt`, с занятым
  местом) — сообщения, музыка, друзья и сообщества, страницы людей и сообществ, картинки, кэш страниц VK,
  собранные данные страниц —
  или всё сразу. Каждое удаление — с подтверждением; открытые экраны забывают удалённое, чтобы не записать его
  обратно. Кэш страниц удаляет WebView при возврате к страницам. Выход из аккаунта стирает всё.

Звук треков не сохраняется: VK отдаёт его зашифрованным потоком, и сохранение означало бы обход защиты.
Без сети список треков виден, но слушать можно только после подключения.

Свой список показывает треки открытой страницы музыки: на главной — «Мои треки» (без рекомендаций),
в плейлисте или альбоме (`/audio?act=audio_playlist…`, по 200 треков, догрузка «Показать ещё») — все его треки.
При переходе между страницами список начинается заново. Без сети сохраняются только «Мои треки».

### Обновление без дёрганья (все свои экраны)
`offline/ListMerge.kt`: если на экране уже есть данные (обычно сохранённые), свежие их не перестраивают —
строки обновляются на местах, новые встают снизу (`stable`); позднее сохранённое только дополняет (`appendMissing`).
В хранилище пишется настоящий порядок (`freshFirst`) — он покажется при следующем открытии или по кнопке «Обновить».
Переписка: сообщения по порядку, новые снизу (плавная прокрутка, если человек внизу), старые из догрузки сверху
с сохранением позиции. Плашка «Нет сети» — поверх списка, не сдвигает его. Без сети WebView берёт уже открывавшиеся
страницы из своего кэша (`LOAD_CACHE_ELSE_NETWORK`).

### Свои списки друзей и сообществ
Настройки → Свои экраны → «Свои списки друзей и сообществ» (включено). Разделы «Друзья» и «Сообщества»
показываются своим экраном поверх страницы VK — так же, как «Мои треки»:
- **Друзья:** аватар с отметкой «в сети», подпись «был(а) в сети вчера в 21:40 · Москва · 2 общих друга»,
  кнопка «Написать» (открывает свою переписку; «Назад» возвращает к друзьям). Сверху — входящие заявки, если есть.
- **Сообщества:** «Мои подписки» — аватар, тематика, число подписчиков, счётчик новых записей.
- **Поиск** по загруженному списку (имя, город, тематика; «ё» = «е»). Пока список неполный, при поиске он догружается сам.
- Нажатие открывает страницу человека (`/id…`) или сообщества (`/club…`); «Назад» возвращает к списку.
- Кнопка «Страница VK» на панели переключает на обычную страницу; если список не пришёл за 12 секунд, страница
  открывается сама. Без сети показывается сохранённый список (только свой — не друзья другого человека).

Откуда данные (снято через `vk_dump.js`, ответы m.vk.ru):
| Список | Метод API | Что берём |
|---|---|---|
| Друзья | `friends.get` (count ≥ 10; превью с count 3 на чужих страницах игнорируются) | `items[]`: имя, `photo_100`, `online_info` (`is_online`, `is_mobile`, `last_seen`, `status`), `city.title`, `mutual.count`, `can_write_private_message`, `deactivated`; всего — `count` |
| Заявки | `friends.getRequests` | `items[]`, если пришли объектами (только id — пропускаются) |
| Подписки | `catalog.getGroups` (`url=…/groups?tab=my`), `catalog.getSection` | порядок — блок с `data_type` `groups_all_groups…` (`group_items[].id`, `counter`), продолжение — его `next_from`; сами сообщества — `response.groups[]` (`name`, `photo_100`, `members_count_text`, `activity`, `type`, `is_closed`) |
| Подписки (запасной путь) | `groups.get` с `extended=1` | `items[]` |

Методы внутри `batch.call` сопоставляются с ответами по `id` из тела запроса. «Сообщества» из меню открываются
адресом `/groups?tab=my` (`query` в `config/Tab.kt`): на главной каталога VK присылает рекомендации и только 8 подписок (они всё равно показываются,
по признаку `is_member`). Если VK переименует блок подписок — поправьте `MY_GROUPS_BLOCK` в `assets/vk_lite/60_people.js`.

### Свои страницы людей и сообществ
Настройки → Свои экраны → «Свои страницы людей и сообществ» (включено). Страница человека или сообщества
показывается своим экраном поверх страницы VK:
- **Шапка.** Человек: фото (нажатие — на весь экран), имя, статус, «в сети» / «был в сети…», город, место учёбы
  или работы, счётчики («29 друзей · 44 подписчика · 6 фото · 34 видео»; друзья, фото и видео открываются).
  Сообщество: обложка, аватар, тематика, число подписчиков, описание (сворачивается). Кнопка «Написать» — если можно.
  Закрытый профиль, закрытое сообщество, удалённая страница — с пояснением.
- **Стена.** Автор и время («вчера в 21:40», «закреплено»), текст (длинный сворачивается, «Показать полностью»;

- Что делается только на странице VK: добавить в друзья, подписаться, лайк, комментарий. Кнопка «Страница VK» на
  панели, «Назад» с неё возвращает к своему экрану. Если данные не пришли за 12 секунд, страница откроется сама.

сразу; короткое имя (`/durov`) — только когда страница прислала данные владельца, разделы сайта (`/feed`,
`/wall1_2`, `/albums1`…) исключены списком `RESERVED`.

### Данные для новых экранов (вместо vk_dump.js)
Настройки → О приложении → «Для разработки» → «Собирать данные страниц». Пока включено, приложение записывает ответы сервера
открытых страниц: откройте нужные разделы, затем «Сохранить собранное…» — файл `vk_dump.json` туда, куда выберете
(разрешения на память не нужны). Обезличивание то же, что в `vk_dump.js`: токены, ключи и подписи — `XXX`,
имена людей, тексты и контакты — `•••(длина)`, у ссылок убраны параметры, из длинных списков — первые 3 элемента.
Названия сообществ, плейлистов и треков остаются. Предел — 10 МБ, сверх него новое не записывается.
Удалить собранное — в «Сохранённых данных». По умолчанию сбор выключен; включайте только на время.

### Срок жизни сессии измеряется, а не угадывается (3.19)
Веб-сессия VK держится токенами и подписями в куках страницы — у приложения прямого доступа к ним нет (это секрет
аккаунта, его даже вырезает сбор дампа). Но видно, когда они протухли: запрос данных отвечает 401/403, либо свой экран
не дождался данных. Время между успешным обновлением и таким признаком — это измеренный срок жизни сессии.

`web/SessionLifetime.kt` (без Android, тест `SessionLifetimeTest`) запоминает самый короткий такой срок за несколько
последних наблюдений, и `SessionRefresher` обновляет сессию заранее — за 80 % от него, а не раз в фиксированные 20 минут.
Пока измерений нет, берётся осторожное значение из настройки «Фоновое обновление» (она же может плановое обновление
выключить). Срок держится в коридоре от 5 минут до 6 часов и переживает перезапуск (`settings/AppSettings.kt`,
ключ `session_lifetime_samples`). Слишком короткое прожитое время (меньше 5 минут) за измерение не считается — это,
скорее, случайный сбой сети, а не истёкший токен. Так «неизвестно, сколько живёт сессия» становится «известно по опыту
этого устройства»: лишних перезагрузок страницы меньше, а данные своих экранов реже оказываются просроченными.

### Работа без открытой страницы VK
Свои экраны берут данные из ответов, которые страница VK получает сама, а эти ответы она подписывает
токенами и ключами из своих скриптов — те со временем протухают. Чтобы не держать страницу открытой всё
время, `web/SessionRefresher.kt` изредка загружает лёгкую страницу VK в том же (невидимом для пользователя)
WebView: её скрипты обновляют куки и подписи, после `onPageFinished` загрузка останавливается. Между
обновлениями страница не трогается — пользователь всё время в своих экранах.

Когда запускается обновление:
- **по требованию** — свой экран не дождался свежих данных (сработал таймаут). Это и есть признак, что
  сессия устарела: экран один раз просит обновление и ждёт данные ещё раз, и лишь если не помогло — уходит
  на страницу VK или показывает плашку. Не чаще `SESSION_REFRESH_MIN_INTERVAL_MS`;
- **планово** — Настройки → Данные и вход → «Фоновое обновление сессии» (по умолчанию раз в 20 мин, можно выключить, оставив
  только обновление по требованию).

Обновление идёт, только пока WebView не виден (открыт свой экран), и не мешает навигации: смена адреса и
ошибки во время обновления игнорируются. Сколько на деле живёт сессия VK — зависит от VK и проверяется на
устройстве; поэтому интервалы вынесены в настройку и `AppConfig`, а не зашиты жёстко.

Что именно обновлять, помогает понять сбор дампа: у каждого запроса он отмечает параметры-подписи
(`signals` в `80_dump.js`) и постоянны ли они в сеансе — по этому видно, что держать свежим.

### Журнал событий и диагностика
Настройки → О приложении → «Журнал и диагностика». Журнал отвечает на вопрос «что происходило перед тем, как не сработало»,
и работает без компьютера: нужный файл формируется и отправляется прямо из приложения.

- **Уровень:** «Выключен» / «Основное» (по умолчанию) / «Подробно» (добавляет каждый принятый и пропущенный
  ответ страницы, размеры записей, пропущенные сохранения).
- **Поделиться отчётом** — собирает файл и открывает системное окно «Поделиться» (почта, мессенджер, облако):
  файл отдаётся через `FileProvider` по временной ссылке, разрешения на память не нужны.
- **Сохранить отчёт в файл…** — то же самое, но записывается туда, куда выберете.
- **Для собранных данных страниц** («Для разработки») добавлено то же «Поделиться собранным». С 4.11 к собранному
  прикладывается отчёт (журнал за то же время), а в самом `vk_dump.json` есть `source` (версия, сборка, Android, WebView,
  устройство) и `summary` (сколько записей, с какого по какое время, из каких окон и страниц — `dev/DumpSummary.kt`).
- Отчёт о сбое тоже отправляется файлом (раньше — обрезаемым текстом) и теперь содержит события перед сбоем.
- Удалить журнал — «Сохранённые данные» → «Журнал событий».

Что в отчёте (один текстовый файл, `diag/DiagnosticReport.kt`): приложение (версия, сборка), устройство (модель,
Android, WebView, экран, память, язык), сеть (тип, проверена ли системой, экономия трафика), все настройки,
сколько что хранится, начало последнего отчёта о сбое и последние до 2000 записей журнала.

Что пишется в журнал (метки): `APP` запуск/закрытие экрана, изменение настроек; `PAGE` загрузка страниц (адрес,
сколько мс, сколько запросов заблокировано и с каких хостов), ошибки загрузки и коды ответов сервера (401/403/429 —
признак проблем с сессией); `SESSION` каждое фоновое обновление сессии (причина, длительность, итог и **сколько
минут прошло после прошлого успешного** — по этому подбирается интервал); `SCREEN` когда открылся свой экран, сколько
мс ждали свежих данных, что решил по таймауту; `SCRIPT` что скрипт страницы принял или пропустил и **ошибки разбора
ответов** (так видно, что VK изменил структуру); `BRIDGE` отклонённые и неизвестные сообщения страницы; `NET` сеть
появилась/пропала; `STORE` сохранения, ошибки чтения, очистка, сокращение кэша картинок; `MESSAGES` свой интерфейс
сообщений; `MEDIA` воспроизведение (с 4.11 — и проигрыватель видео: качество, скорость, громкость жестом); `DUMP`
сбор данных.

С 4.11: в строке «процесс запущен» — версия, сборка и Android (журнал переживает обновления, и так видно, какая
сборка писала строки дальше). Необработанные ошибки скриптов документа (`shared/net_tap.js`, `window.__vkErrorTap`):
ошибка своего скрипта — `SCRIPT` предупреждением с номером строки («ошибка скрипта приложения: … @12:5»), ошибки
скриптов VK — только в подробном журнале и только с сервером; первые 20 на документ, длинные числа скрыты.

Чего в журнале нет (проверено тестами и при просмотре кода): имён людей и сообществ, текстов сообщений и записей,
содержимого страниц, куки и токенов. Адреса очищаются (`LogFormat.url`): без параметров, длинные числа в пути
(id людей и записей) заменены на `#` — `m.vk.com/id#`. Хранится до ~800 КБ (два файла по 400 КБ), старое вытесняется.

Как добавить запись: `AppLog.i(LogTag.SCREEN, "сообщение", "поле" to значение)`; в скрипте страницы —
`Diag.warn('сообщение')` (`assets/vk_lite/40_screens.js`: одинаковое — один раз на страницу, не больше 60 на страницу).
Новая область — значение в `LogTag`.

### Очередь неотправленных сообщений
Сообщение сразу попадает в очередь на диске и показывается в переписке справа с пометкой и значком («Ждёт отправки»,
«Отправляется…», «Не подтверждено», «Не отправлено»); в списке диалогов у такого собеседника — значок часов.
Очередь переживает закрытие приложения (`outbox/`, `offline/outbox.json`). Удалить — «Сохранённые данные» → «Неотправленные сообщения».

Кнопка «Отправить» на странице VK — это нажатие кнопки, и ответ «нажата» не значит «принято сервером». Поэтому
доставку подтверждает только появление в переписке настоящего сообщения (id вида `c<номер>`) с тем же текстом, которого
не было при нажатии (`outbox/OutboxLogic.kt`, `reconcile`). Отсюда правила:
- повторяется само только то, что точно не уходило (нет сети, страница не приняла ввод): с нарастающей паузой, после 5 неудач —
  «Не отправлено»;
- сомнительное (нажали, подтверждения нет за 45 с или приложение закрылось) само не повторяется — иначе дубль. Если оно
  появится в переписке, пометка снимется сама; иначе человек выбирает «Отправить ещё раз» или «Удалить»;
- одно сообщение «в полёте» на переписку, порядок сохраняется; сомнительное и неудавшееся очередь не блокируют.

Ограничение: если страница отдаёт сообщения не через API, а только вёрсткой, номеров нет и доставка не подтвердится
(сообщение останется «Не подтверждено», хотя могло дойти).

### Фоновая проверка новых сообщений и уведомления
Настройки → «Сообщения». Системный `JobScheduler` (без новых библиотек; `sync/`) раз в 15/30/60 минут при сети запускает
`MessageSyncService`: невидимое окно (`HeadlessSync`) открывает мессенджер, забирает диалоги, сохраняет их (приложение
открывается уже свежим) и показывает уведомление (`MessageNotifier`). Порядок работы — в `SyncMachine` (без Android,
проверяется тестами). Одноразовое задание отправляет очередь, как только появится сеть. Пока открыт экран сообщений,
фоновая работа не запускается: экран сам обновляется (раз в 30/60/120 с или выкл) и сам отправляет очередь.

Что считается новым (`sync/NewMessages.kt`): VK не присылает число непрочитанных, только «диалог непрочитан» и текст
последнего сообщения. Новое — непрочитанный диалог с другим последним сообщением, чем то, о котором уже сообщали. Первый
снимок только запоминается (без лавины уведомлений). Два одинаковых «ок» подряд без прочтения второго уведомления не дадут.
На заблокированном экране в уведомлении — только общая надпись. Разрешение на уведомления (Android 13+) спрашивается один
раз при открытии экрана сообщений.

#### Группа уведомлений (4.48)
У каждого непрочитанного диалога — своё уведомление с «Ответить» и «Прочитано»; от двух — Android сворачивает их под
сводку «Новые сообщения». Звук один: в группе звучит сводка (если новое пришло в диалог со звуком), одиночное — само.
На каждой проверке шторка сверяется со списком (`NotifyGroup.plan`): новое ставится, прочитанное убирается, остальное не
трогается; смахнутое без нового не возвращается. Номера: сводка 2001, диалоги 2002 с меткой `peer:<номер>`.

#### Общие настройки и свои у диалога (4.47)
Настройки → Сообщения → «Уведомления»: общий переключатель (выключение сразу убирает показанное), «Текст в уведомлениях»,
«Настройка диалогов» (список со своей настройкой, «Сбросить все») и «Звук и вибрация» (системный экран канала).

У каждого диалога — своя настройка на этом телефоне (долгое нажатие на диалог → «Уведомления на этом телефоне…» или
«Уведомления» в меню переписки). Сеть не нужна, аккаунт VK не меняется:
| Режим | Попадает в уведомление | Звук |
|---|---|---|
| Как в VK (по умолчанию) | если беседа не выключена в VK | да |
| Всегда | да, даже если выключена в VK | да |
| Без звука | да | нет (канал `messages_silent`) |
| Не уведомлять | нет | — |

«Скрывать текст сообщений» — в уведомлении имя и «Новое сообщение». Уведомление звучит, если новое пришло хоть в один
диалог со звуком; иначе обновляется молча. Важность канала после создания меняет только человек в Android, поэтому
тихий — отдельный канал. Настройки диалогов — в своём файле (`dialog_notify`, с именами): не переезжают на новый
телефон, стираются при выходе.

### Скрытие сведений об устройстве
Настройки → Реклама и трекеры → «Скрывать сведения об устройстве» (включено; применяется после перезапуска приложения). Пять уровней:
1. **User-Agent** (`web/UserAgent.kt`): без модели, сборки и версии Android — `Android 10; K`, версия Chrome без
   дробной части (как у сокращённого User-Agent самого Chrome). Маркер WebView убирается всегда: по нему VK показывает заглушку.
2. **Заголовок X-Requested-With** (имя пакета приложения) отключён.
3. **Скрипт подмены** (`assets/privacy.js`, до скриптов VK): ядра и память, платформа, тип сети, батарея, подсказки о клиенте
   (`userAgentData`), размеры экрана (заменены размером окна), плотность пикселей (целое число), режимы системы в медиа-запросах
   (доступность, контраст, анимации; тема не трогается), датчики, объём памяти и места, видеокарта WebGL, отпечаток canvas
   (невидимая правка небольших холстов). Каждая подмена независима: сбой одной не ломает остальные и страницу.
4. **Телеметрия VK** блокируется (`TRACKER_DOMAINS`, `TRACKER_PATHS_ON_VK`): `statEvents.*`, `stats.track*`, `apptracer.ru`,
   `tracker-api.my.com`. Заблокированному запросу данных отвечаем «успех» с заголовками CORS, чтобы скрипты VK не слали его снова.
5. Геолокация запрещена.

Чего скрыть нельзя и почему: часовой пояс и язык (нужны для времени и текстов), размер окна (нужен для вёрстки), всё, что VK
получает от самой учётной записи. Запросы, вложенные в `batch.call`, по пути не отличить — они проходят.

### Назад, картинки, музыка
- **«Назад»** (`web/BackPolicy.kt`): с главной страницы раздела (открытой при входе или из меню) закрывает приложение, а не листает
  внутреннюю историю страницы VK (она уводила на веб-версию). Внутри раздела (профиль, запись) возвращает на шаг.
- **Кэш картинок** (`offline/ImageKey.kt`): ключ — путь и вид картинки (`size`, `crop`…) без подписи (`sign`, `c_uniq_tag`) и без
  сервера (`sun1-18` / `sun9-46`): раньше одна и та же картинка с новой подписью скачивалась заново. Аватарки списков и
  первые фото записей сообществ скачиваются заранее (`ImageCache.prefetch`), только по безлимитной сети.
- **Музыка**: «есть ещё» теперь определяется и по кнопке «Показать ещё» в вёрстке (первая порция приходит без ответа сервера, и
  догрузка не включалась), а короткий список, целиком поместившийся на экране, догружается сам (`LoadMoreTrigger.onListChanged`).
- Кнопка «Открыть в браузере» убрана.

### Просмотр фото и листание
Фото открывается на весь экран (`ui/PhotoViewerActivity.kt`). Если фото несколько — в записи сообщества или человека, в
сообщении — их листают жестом в стороны, сверху видно «2 / 5» (`ui/PhotoGallery.kt`). Открывается то, на которое нажали, а
превью видео в просмотр не попадают (они ведут на страницу видео). Соседние фото скачиваются заранее (`ImageCache.warm`), и
листание не ждёт сети.

Жест (`ui/PageGesture.kt`, проверен тестами): листает либо быстрый бросок, либо медленное, но длинное движение (за четверть
ширины экрана), и только если оно идёт больше вбок, чем вверх-вниз. У увеличенного фото палец двигает саму картинку:
листает только бросок и только когда картинка уже упёрлась в край. Щипок и двойное касание работают как раньше; нажатие на фото
закрывает просмотр (раньше клик до слушателя не доходил, и закрыть можно было только кнопкой «Назад»).

### Оформление интерфейса
Нормы, по которым сделан весь интерфейс (новые экраны должны им следовать; проверяются тестом `ui/UiStyleTest.kt`):
- **Цвета** — в разметке, значках и коде (4.1) только из палитры (`values/colors.xml`: семейства `ink_*`, `paper_*`, `signal_*`, `media_*`) и темы (`?attr/colorOnSurface`,
  `?attr/colorPrimary`, `?attr/colorOutlineVariant` для разделителей). Литералов `#RRGGBB` в разметке и значках нет. Оттенок, который
  у тёмной и светлой темы разный (зелёный «в сети»), — атрибут темы (`colorOnline` в `values/attrs.xml`). Затемнение под подписями на
  фото — `media_scrim`.
- **Отступы** — из сетки 2, 4, 6, 8, 10, 12, 14, 16, 20, 24, 28, 32, 56 dp; списки — 16dp по краям, строка с аватаром — 52dp с
  отступом 14dp до текста, внизу списка запас 72dp под плашку «нет сети».
- **Нажимаемое** — не ниже 48dp (кнопки, счётчики в шапке, ряд действий под записью).
- **Плашки и подписи** — плашка внизу в форме `offline_pill` (скругление 20dp), текст через тире: «Нет сети — показано сохранённое».
  Подпись пункта настроек — до 136 знаков (как самая длинная из исходных), без перечислений; списки в настройках показывают выбранное
  значение. Подробности — здесь, в README, а не в подписи.
- **Поля** — без рамок; поиск — скруглённая плашка цвета `colorSurfaceContainerHigh`, как остальные поверхности.
- **Названия разделов настроек** — до трёх слов («Хранилище», «Журнал и диагностика»).
- **Состояния без данных** (4.51) — `layout/view_empty_state.xml` через `ui/EmptyState.kt`: значок 48dp, заголовок
  `textAppearanceTitleLarge`, пояснение `textAppearanceBodyMedium`, кнопка действия (и вторая — контурная), по центру,
  отступ `content_padding` (24dp). Своя строка текста вместо этого — не нужна (`UiStyleTest`). Загрузка — индикатор с задержкой.
