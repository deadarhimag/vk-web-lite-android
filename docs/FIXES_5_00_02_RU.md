# Исправления повторного ревью — 5.00.02

Версия исходников: **5.00.02**, versionCode **210**. Идентификатор приложения и настройки подписи сохранены.
Исходные архивы 5.00.00 и 5.00.01 не изменялись.

## Четыре исправления

1. **Отменённые файлы не уходят со следующим текстом.** После передачи файлов в композер VK отмена помечает документ как требующий очистки. Все дальнейшие отправки из этого композера блокируются самим JS, включая текст, который уже успела передать Kotlin-очередь. Страница сообщает Android о необходимости сброса. Android снимает готовность очереди и загружает новый документ актуальной переписки/списка диалогов: это очищает и input, и внутреннее состояние загрузки VK. Повтор передачи разрешается после загрузки чистой страницы. После успешного нажатия отправки этот сброс не запускается.

2. **Подтверждения не используются повторно.** Событие delivered передаёт `peerId + cmid`. Ответ без серверного номера сам по себе больше не удаляет сообщение; подтверждение ожидается по истории. Номера, уже использованные для подтверждения, записываются в оставшиеся записи очереди. Общая для UI и фоновой работы граница подтверждённых номеров живёт в Outbox и защищает новые сообщения даже после опустошения очереди. При выходе/очистке очереди она сбрасывается. Если одновременно ожидаются одинаковые тексты и нельзя определить, какой из них доставлен, автоматическое подтверждение блокируется для этих записей, а сами записи сохраняются. По таймауту они показываются как неподтверждённые; человек может проверить историю и удалить запись либо явно повторить её. Такая блокировка сохраняется в JSON и не снимается простым удалением соседней записи.

3. **Остановка до dispatch не делает сообщение сомнительным.** SyncMachine отдельно помнит команду, которая ещё ждёт сохранения и не передана странице. Таймаут шага, потеря входа и завершение HeadlessSync возвращают такую запись в QUEUED и ставят сохранение обновлённого состояния. Перед передачей команды странице executor отмечает фактический dispatch. После этой границы таймаут/отмена уже не разрешают автоматический повтор: отправка могла начаться. Это не обещание определить результат при внезапной смерти процесса между сохранением SENDING и передачей команды; в таком окне по-прежнему требуется осторожное UNCONFIRMED.

4. **Голосовое не блокирует очередь без срока.** Вся JS-операция ограничена 120 секундами. AbortSignal передаётся и в upload fetch, и в API-запросы, включая повтор после обновления авторизации. Отмена снимает таймер и прерывает доступные запросы; поздние результаты не продолжают цепочку. На Android есть запасной таймер 150 секунд на случай остановки таймеров страницы или отсутствия ответа JS. Результат содержит номер операции: ответ старой передачи не завершает новую. После завершения/таймаута флаг занятости снимается и текстовая очередь возобновляется. Если `messages.send` уже начался, отображается «доставку не удалось подтвердить» с просьбой проверить переписку перед повтором; автоматического повтора голосового нет.

JSON очереди расширен полями `confirmedThrough` и `confirmationBlocked` с безопасными значениями по умолчанию. Старые файлы читаются без миграции. Полноценная корреляция всех действий страницы по requestId остаётся отдельной задачей; при недостаточных данных эта версия сохраняет неоднозначные сообщения вместо угадывания доставки.

## Проверено

- **100 изолированных JVM-тестов, 0 ошибок.** Это существующие проверки и новые сценарии повторных подтверждений, пустой очереди, неоднозначных текстов, таймаута/отмены до dispatch и после него. В число входят 5 локальных тестов настоящего Outbox с управляемой границей записи.
- **22 JS-регрессии, 0 ошибок.** Запускаются настоящие функции страницы с управляемыми DOM/API/таймерами. Новые сценарии: отправка обычного текста после отменённого вложения; чистая страница; успешное вложение без лишнего сброса; зависания каждого этапа голосового; поздний успех; запрет сетевого повтора после отмены во время обновления авторизации.
- **446 Kotlin-файлов без синтаксических ошибок** по PSI. Это не полная Android-компиляция.
- **145 XML-файлов корректно разбираются.**
- Локальные дополнительные воспроизведения повторного ревью преобразованы в проверки исправленного поведения.

В изолированном JVM-наборе используются заглушки Android/JSON, **3 теста сериализации явно исключены**. Проверка новых JSON-полей добавлена в штатный тест сохранения; в изолированном запуске она не исполняется. Разбор новых payload-полей также проверяется штатным Android/JVM-набором, который здесь не запускался успешно.

Полная Android-сборка/APK/lint не подтверждены: в окружении Java 11 JRE, а штатный Gradle останавливается на `Module jdk.unsupported.desktop cannot be found in the module graph`; для проекта требуется JDK 17 и Android SDK. Полный jsdom-набор недоступен из-за отсутствующего модуля jsdom; обычный node --test также получает spawn EPERM в этой среде. Ошибки окружения не считаются успешными проверками.

Реальная страница VK, устройство/эмулятор, работа AbortController в установленном WebView и восстановление после смерти процесса не проверялись. Особенно нужна приёмка отмены после начала загрузки файла, смены чата во время сброса композера, сетевого зависания голосового и повторного открытия переписки с одинаковыми неподтверждёнными сообщениями.

## Запуск в обычной среде

Из корня проекта с JDK 17 и Android SDK:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug assembleRelease --no-daemon
cd tests/js
npm ci
npm test
```

Без npm-зависимостей: `node review-checks.cjs` из корня проекта.

Локальный результат текущей проверки — `CHECK_RESULTS.txt`. Вспомогательные компиляторы, бинарники и `.review-tools` в распространяемый ZIP не включены. Архив содержит исправленные исходники, **APK не собран и не подписан**.
