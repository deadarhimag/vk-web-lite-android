# Исправления VkWebLite 5.00.01

Работы выполнены по ревью версии 5.00.00. Идентификатор приложения сохранён; версия исходников повышена до 5.00.01, versionCode 209. Исходный ZIP 5.00.00 не изменён.

## Что исправлено

| № из REVIEW_RU.md | Изменение |
|---|---|
| 1. Отмена вложений | Каждая передача получает уникальный токен и исходный peerId. Отмена доходит до JS; callback проверяет токен и текущую переписку перед загрузкой, ожиданием и нажатием отправки. Повторная проверка есть внутри Kotlin main.post. Таймаут также отменяет передачу. |
| 2. Голосовое после смены чата | VoiceComposer инвалидирует ожидающий результат stopAsync при уходе/смене переписки. Устаревший файл удаляется. Передача голосового также привязана к токену и peerId; отменённые шаги не продолжают отправку. |
| 3. Сохранность outbox | Появилось подтверждение успешной записи. UI очищает текст после commit; при ошибке оставляет его в поле. Приёмник ответа из уведомления ждёт commit перед завершением goAsync. Отправка странице/через API ждёт сохранения SENDING. При смене чата, остановке экрана или очистке очереди отложенный dispatch не выполняется. |
| 4. Потеря renderer | ReaderPageClient уничтожает повреждённый WebView и сообщает владельцу. Экран сообщений пересоздаётся; фоновая работа безопасно завершается. MusicCacheWorker освобождает повреждённое окно и продолжает следующую порцию в новом. |
| 5. Потеря части файлов | Если выбранных файлов несколько, а input не поддерживает multiple, операция завершается явной ошибкой до отправки. Обрезание списка до первого файла удалено. |
| 6. Коллизия hashCode | Дедупликация записей OfflineStore использует SHA-256 вместо 32-битного String.hashCode. |
| 7. Небезопасная замена файла | DurableTextFile записывает временный файл, делает fsync и атомарную замену в той же папке. Ошибка замены сохраняет предыдущую версию и передаётся вызывающему коду. Удаляющего оригинал fallback нет. |
| 8. Очистка картинок | Задачи захватывают поколение кэша. Старые результаты не публикуются в файлы, память или UI после очистки. Проверка и публикация синхронизированы с удалением. Недействительные временные файлы удаляются. |
| 9. Смешивание историй | В пачке история хранится по peerId. Flush назначается при первом элементе; последующие сообщения не переносят его бесконечно. |
| 10. Поздний retry | Время повтора выбирается по ближайшей готовой переписке с сохранением порядка внутри неё. Будущие запланированные сообщения не задерживают обычную очередь. |
| 11. Лимит объёма | Потоки провайдеров сначала копируются с подсчётом реального объёма: максимум 12 МБ на файл и 24 МБ суммарно. Затем передаются кусками без полного ByteArray файла. JS дополнительно проверяет размеры, количество и метаданные частей. |
| 12. Рост JS-истории | В памяти остаётся не более 16 переписок с сохранением открытой. При превышении 2032 записей bucket сокращается до последних 2000. Ограничивается само хранилище, а не только сериализуемый ответ. |
| 13. Lock музыкального кэша | Поколение читается через volatile без ожидания файлового lock. Запрос кэширования из UI больше не ждёт миграцию/запись MP3 ради чтения поколения. |

Дополнительно: одинаковые события завершения разных отправок не отбрасываются как дубликаты; выбор времени отправки проверяет исходную переписку; очистка outbox инвалидирует старые ожидания загрузки/commit. Завершённые base64-части освобождаются после сборки File; оставшиеся после завершения процесса временные вложения очищаются при следующем запуске.

Надёжность очереди улучшена с сохранением существующего формата JSON, без миграции пользовательских данных в новую БД. Неограниченные executor-очереди, полноценная корреляция всех команд/ответов по requestId и политика блокирующего lint остаются отдельными архитектурными улучшениями из раздела дополнительных рекомендаций исходного ревью.

Штатный Gradle-набор использует настоящую org.json и включает эти тесты. В проект добавлены 11 JUnit-регрессий; ещё четыре теста контракта Outbox находятся во вспомогательной `.review-tools`.

Результат запуска: `CHECK_RESULTS.txt`. Локальные вспомогательные исходники проверки — `.review-tools`; скачанные дистрибутивы, библиотеки и бинарные результаты в исправленный ZIP не включены.

## Проверка в обычной среде разработки

На машине с JDK 17 и Android SDK выполнить из корня проекта:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug assembleRelease --no-daemon
```

Для скриптов:

```powershell
cd tests/js
npm ci
npm test
```

Новые JS-регрессии можно выполнить без npm-зависимостей: `node review-checks.cjs` из корня проекта. Они также включены в штатный `npm test` и будут запускаться в существующем GitHub Actions workflow.

Перед установкой рабочей сборки проверить на устройстве: смену чата в момент отправки файлов/завершения записи; отмену в последние 120 мс перед нажатием отправки; выход/очистку при активной загрузке; завершение процесса после ответа из уведомления; нехватку места; потерю renderer при одновременно открытых окнах; длительную навигацию и миграцию большого музыкального кэша.

APK не собран и не подписан. Архив содержит исправленные исходники; для обновления установленного приложения потребуется прежний ключ подписи.
